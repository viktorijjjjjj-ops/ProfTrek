# Концепция регионального цифрового агента «БюроНет СПО»

## Цель

Снизить время, которое руководители и сотрудники профессиональных образовательных организаций тратят на поиск, повторный ввод, сверку и представление одних и тех же сведений, без снижения качества государственного управления и достоверности отчетности.

## Пользователи

| Роль | Возможности |
|---|---|
| Сотрудник ПОО | Получает задачи, загружает запрос, проверяет и подтверждает подготовленный ответ |
| Руководитель ПОО | Контролирует сроки, нагрузку подразделений и согласует документы |
| Региональный координатор | Управляет реестром запросов, календарем и правилами исключения дублей |
| Владелец показателя | Подтверждает источник, методику расчета и период актуальности данных |
| Аналитик | Анализирует обезличенную нагрузку и готовит предложения по ее сокращению |
| Администратор | Настраивает роли, интеграции, справочники и аудит |

## Сквозной сценарий

1. Запрос поступает в единое окно или загружается сотрудником.
2. Агент извлекает инициатора, срок, основание, отчетный период и перечень показателей.
3. Каждый показатель сопоставляется с региональным реестром данных.
4. Агент ищет полные и частичные совпадения с ранее представленными сведениями.
5. При наличии дубля формируется проект мотивированного ответа со ссылкой на источник.
6. При отсутствии дубля доступные поля заполняются из доверенных систем.
7. Владелец данных проверяет расхождения, сотрудник подтверждает итоговый документ.
8. Система фиксирует отправку, версию, источник каждого значения и фактические трудозатраты.

## Функциональные модули

- единый реестр запросов;
- нормативный календарь отчетности;
- паспорт показателя: определение, единица, периодичность, источник, владелец;
- поиск текстовых и смысловых дублей;
- безопасный помощник для подготовки проектов документов;
- маршруты проверки и согласования;
- аналитика нагрузки по ПОО и подразделениям;
- реестр решений об отмене, объединении и автоматизации запросов;
- уведомления о сроках и расхождениях;
- журнал действий и версий.

## Метрики результата

| Показатель | Целевое значение пилота |
|---|---:|
| Сокращение времени на подготовку типового ответа | не менее 40% |
| Доля полей, заполненных из доверенных источников | не менее 60% |
| Сокращение повторных запросов | не менее 25% |
| Доля ответов с просрочкой | не более 5% |
| Точность выявления потенциальных дублей | не менее 90% |
| Документы, отправленные без проверки человеком | 0% |

## Ограничения

- Агент не принимает юридически значимые решения и не подписывает документы.
- Совпадение запросов является рекомендацией до подтверждения ответственным.
- Ответ должен быть воспроизводим: источник каждого значения хранится вместе с версией.
- Обработка персональных данных выполняется только в аттестованном защищенном контуре.
- Нормативная база и шаблоны проходят регулярную проверку профильным подразделением.

## Этапы внедрения

| Этап | Срок | Результат |
|---|---|---|
| Обследование | 4 недели | карта отчетности, базовый замер нагрузки, владельцы данных |
| Проектирование | 4-6 недель | модель данных, регламент, UX и требования к защите |
| MVP | 10-12 недель | реестр запросов, календарь, поиск дублей, проекты ответов |
| Пилот | 8 недель | эксплуатация в 5-7 ПОО и оценка метрик |
| Тиражирование | 3-4 месяца | подключение всех ПОО и региональных интеграций |

## Управленческий эффект

Регион получает не только средство автоматизации отдельных отчетов, но и измеримый механизм постоянного сокращения нагрузки: видно, кто запросил сведения, где они уже существуют, сколько времени потребовалось на ответ и какое решение позволит исключить повторную работу в будущем.
